# Challenge #3 ★★★ お客様のスマホから注文できない！

## 症状

> スタッフ「伝票は見えるようになりました！でも、お客様のスマホ（このアプリ）から注文するとダメみたいです…お店の端末では注文できるのに」

お客様アプリの「📱 ご注文」から注文すると、次のエラーになります。

```
お店と通信できませんでした（ブラウザがブロックした可能性があります。F12 → Console を確認）
```

ところが、メニューや伝票の表示（`GET`）は問題なくできています。

## ミッション

お客様アプリ（ブラウザ）から注文（`POST /orders`）を送れるようにしてください。

直せたら Challenge #3 の「クリア判定」を押します。✅ が出ればクリアです。判定では中身が空の注文を送り、お店から返事が届くかだけを確かめるので、伝票は増えません。

## まずは開発者ツールを開こう

このチャレンジは、CloudWatch Logs を見ても手がかりがありません。エラーはお店（AWS）の中ではなく、お客様のブラウザの中で起きているからです。ブラウザの中を見るための道具が、開発者ツールです。

開き方は次のとおり。Chrome か Edge がおすすめです。

| OS | 開き方 |
|---|---|
| Mac | `⌥ Option` + `⌘ Command` + `I` |
| Windows | `F12`、または `Ctrl` + `Shift` + `I` |
| 共通 | ページ上で右クリック →「検証」 |

開発者ツールを開いたまま、もう一度「注文する」を押してみてください。見るのは次の2つのタブです。

- Console タブ：赤い文字のエラーが出ていないか。英語ですが、キーワードを拾えれば十分です
- Network タブ：`orders` へのリクエストがいくつ飛んでいて、それぞれどんなステータスで返ってきたか

## 調べるとよい場所

- 開発者ツールの Console タブと Network タブ
- API Gateway の `aws-cafe-<環境ID>-api` のリソース `/orders`

## 切り分けのヒント

スタッフの言う「お店の端末」は、API Gateway コンソールのテスト機能のことです。`/orders` の `POST` を選んで「テスト」タブから注文を送ると、こちらはちゃんと届きます。つまり API そのものは動いていて、ブラウザから呼んだときだけ失敗している、ということです。

## 知っておくとよい言葉

CORS は、ブラウザが「別のサイトの API を呼んでいいか」を確かめるしくみです。

JSON を `POST` するとき、ブラウザは本番の注文を送る前に `OPTIONS` で「送ってもいいですか？」とお店に聞きます。これをプリフライトと呼びます。`GET` だけならふつうはこの確認は起きません。GET は動くのに POST だけ動かない、という今回の症状のヒントはここにあります。

それから、API Gateway は設定を変えただけではお客様に届きません。デプロイして初めて反映されます。

> 💡 設定がうまくいったかどうかは、画面上部の通知ではなく、設定そのものを見て確かめてください。上部の通知には、前の操作の結果が残っていることがあります。運営もこれで一度「デプロイできてる」と勘違いしました。

このチャレンジはいちばん難しいので、詰まったら遠慮なく「店長のつぶやき」を見てください。
