# 01. はじめに（ログインとアプリの準備）

## 1. AWS アカウントへのログイン

運営から案内された方法で、ハンズオン用 AWS アカウントのマネジメントコンソールにログインします。

ログインしたら、画面右上のリージョンが「アジアパシフィック（東京） ap-northeast-1」になっているか見てください。違うリージョンだと、用意したリソースが1つも見つかりません。

自分の環境ID（例: `team01`）も確認しておきましょう。AWS のリソースには、`aws-cafe-team01-api` のように環境IDが付いています。同じアカウントにほかのチームの環境が入っていることもあるので、自分の環境IDが付いたリソースだけを触ってください。

> 💡 このアカウントは今日のハンズオン専用です。何を触っても本番環境には影響しないので、安心していろいろ見てみてください。

## 2. お客様アプリを開く

運営から配られた「チーム専用のアプリ URL」を、PC のブラウザ（Chrome / Edge / Firefox など）で開きます。お店の接続先は URL に入っているので、開くだけで始められます。画面の左上に「環境：team01」のように、自分の環境IDが表示されます。

「お店の URL が指定されていません」と出たら、URL の一部が欠けています。配られた URL をもう一度、まるごとコピーして開き直してください。

## 3. アプリの見方

| 画面の場所 | 内容 |
|---|---|
| 📋 本日のミッション | 4つのチャレンジ。今のチャレンジだけが開いている。見出しを押すとほかのチャレンジも開ける。直したら「クリア判定」を押す |
| 店長のつぶやき | ヒント。押すたびに1つずつ出る（各チャレンジ3段階）。リソース名には自分の環境IDが入る |
| 📖 メニュー | `GET /menu` の結果 |
| 📱 ご注文 | `POST /orders` で注文を送る |
| 🧾 厨房の注文伝票 | `GET /orders` の結果（DynamoDB の中身）。新しい伝票ほど上に出る |

開いた時点で、メニュー欄にも伝票欄にも、もうエラーが出ているはずです。ここからスタートです。まずはメニューから直していきましょう。

本来どう動くはずだったのかを見たくなったら、URL の末尾を `?local=1` にしてローカル版を開いてみてください。開発担当のパソコンで動いていたときのお店が、AWS に接続せずにそのまま動きます。元に戻すときは、配られた URL を開き直します。

## 4. 進め方のコツ

迷ったら、次の順で考えると原因にたどり着きやすくなります。

1. 症状を確認する（アプリで何が起きている？）
2. 日報（ログ）を見る（店員さんは何と言っている？）
3. 原因を直す（コード？権限？窓口の設定？）
4. 反映する（Deploy / 保存 / API のデプロイ）
5. アプリでクリア判定を押す

いちばん忘れやすいのは 4 の「反映」です。直したつもりでも、反映していなければお客様には届きません。

チャレンジは #1 から順に進めてください。
